# 开发规范

## Git 工作流规范

### 提交后自动推送
**规范要求**：执行 `git commit` 命令后，立即执行 `git push` 推送到远程代码库

**原因**：
- 保持本地与远程同步
- 避免代码丢失
- 团队协作更及时

**工作流程**：
```bash
# 1. 查看状态
git status

# 2. 添加文件
git add <file>...

# 3. 提交（使用规范的提交信息）
git commit -m "feat: 描述变更内容"

# 4. 立即推送
git push
```

## 提交信息规范

### 类型前缀
使用以下前缀之一开头：

| 前缀 | 说明 | 示例 |
|------|------|------|
| `feat:` | 新功能 | `feat: 添加数学口算练习功能` |
| `fix:` | 修复 bug | `fix: 修复拼音练习提交错误` |
| `refactor:` | 代码重构 | `refactor: 优化语文练习页面架构` |
| `docs:` | 文档更新 | `docs: 更新开发规范文档` |
| `style:` | 样式/格式调整 | `style: 调整页面间距` |
| `test:` | 测试相关 | `test: 添加单元测试` |
| `chore:` | 构建/工具链 | `chore: 更新依赖版本` |

### 提交信息结构
```
<type>: <subject>

<body>
```

**示例**：
```
refactor: 优化语文练习页面架构，提升代码质量

- 主页面从 580+ 行 → 114 行，减少 80%
- 创建 useChinesePractice composable 管理练习逻辑
- 创建 PracticeModeRouter 组件处理练习模式切换
- 添加优化计划和总结文档
```

## 代码优化规范

### 1. 组件化原则
- **单一职责**：每个组件只负责一个功能
- **可复用性**：通用组件抽离到 `components/` 目录
- **命名规范**：组件名使用 PascalCase，文件使用 kebab-case

### 2. Composables 使用
- **业务逻辑抽取**：复杂业务逻辑优先使用 Composables
- **命名规范**：以 `use` 开头，如 `useChinesePractice`
- **存放位置**：`src/composables/` 目录

### 3. 常量定义
- **消除魔法字符串**：所有字面量常量定义在 `src/constants/`
- **类型安全**：配合 TypeScript 使用 `as const` 获得完整类型推断
- **常量文件组织**：按功能模块分文件，如 `chinese.ts`、`math.ts`

### 4. TypeScript 类型
- **完整类型覆盖**：所有变量、函数、组件 Props 都要有类型
- **类型复用**：类型定义在 `src/types/index.ts` 中
- **类型安全优先**：避免使用 `any`，使用 `unknown` 或精确类型

### 5. SOLID 原则遵循
- **SRP (单一职责)**：每个函数/组件只做一件事
- **OCP (开闭原则)**：对扩展开放，对修改关闭
- **LSP (里氏替换)**：子类可以替换父类
- **ISP (接口隔离)**：接口小而专一
- **DIP (依赖倒置)**：依赖抽象而非具体实现

## 代码结构规范

### 目录结构
```
src/
├── components/        # 组件
│   ├── chinese/      # 语文模块组件
│   ├── english/      # 英语模块组件
│   └── math/         # 数学模块组件
├── composables/       # Composables
├── constants/         # 常量定义
├── store/            # Pinia 状态管理
├── pages/            # 页面
├── types/            # 类型定义
└── utils/            # 工具函数
```

### 文件命名
- **组件文件**：PascalCase，如 `TextbookTab.vue`
- **Composables**：camelCase，以 `use` 开头，如 `useChinesePractice.ts`
- **常量文件**：kebab-case，如 `chinese.ts`

## 开发最佳实践

### 1. 重构流程
1. **分析问题**：识别代码痛点和改进点
2. **制定计划**：创建优化计划文档
3. **渐进重构**：小步快跑，每步可回退
4. **保持功能**：重构不改变功能，只改进代码结构
5. **记录总结**：完成后创建总结文档

### 2. 优化指标
- **代码行数**：目标减少 30%-50%
- **组件数量**：合理拆分，单一职责
- **可维护性**：代码清晰，易于理解
- **可测试性**：逻辑独立，易于测试
